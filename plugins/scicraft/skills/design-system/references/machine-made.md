# What reads as machine-made

Each pattern below was built by an assistant and removed at the author's request. The replacement is what the author kept.
"Make it cleaner" or "more minimal" means removing these inside the same look; a new look for the same request lost
every time.

## 1. Across media

| Pattern | Use instead |
|---|---|
| a card with a rounded border and a short claim | the sentence, plain, large |
| three columns, each with a bold header and two lines | one sentence and one picture, or three separate units |
| boxes joined by arrows to explain a method | the paper's own figure |
| a numbered list with large numerals | nothing; the order of the work is the list |
| a punchline in the accent color | the title already says it |
| pill-shaped labels | plain labels on ground-colored plates |
| statistic tiles in a row | numbers in the order of the argument, on one line |
| a decorative gradient, glow, glass or icon | the data |
| drop shadows | none, except a floating tooltip or dialog |
| initials in a disc for a missing photo | the real photo, or name and role as text |
| a provenance caption under each picture | the caption file, the speaker, the notes |
| "·", "•", a vertical bar or "/" between phrases | nothing, or one sentence ("the × was way better, but you can also drop it") |
| "A × B × C" chains of fields | one concrete sentence |
| a tagline or eyebrow over the title | the name, very large |
| ALL-CAPS labels, slogans, fake-terminal tags ("[CONTRIBUTION_LOG]") | plain sentence-case words |
| a second typeface, a monospace face for display | Helvetica Neue, weight changes only |
| a figure on a white plate in a dark medium | the figure recolored |
| neon accents | Okabe-Ito or the locked palette |

## 2. Web page

| Pattern | Use instead |
|---|---|
| an abstract or TL;DR at the top | three statements and the main claim, about 40 words |
| a result claim above the fold ("ranked first of N") | the claim beside its evidence |
| a table and a heat map of the same data | the heat map open, the table in a fold |
| a robustness section nobody asked for | dropped |
| affiliation footnote lists in two columns | the footer marks |
| key-contribution lists, news boxes | nothing |
| ten cards for an ablation | one heat map |
| nested folds, folds open by default | one level, closed |
| looping animation | rise once, play once, honor reduced motion |

## 3. Slide

| Pattern | Use instead |
|---|---|
| small gray captions and footers | one ink, 28 px and more |
| 40 words on a slide | 25, counted |
| a question and its answer on one slide | the question; the answer is spoken |
| formulas for a non-specialist audience | the picture; math in backup |
| a footer with all section tabs ("crowded") | the current section only |
| redrawn charts and diagrams ("really low quality figures") | the paper's and the website's own |
| a code card for non-programmers | backup, if at all |
| colors without a key | a legend on every such slide |

## 4. Data figure

| Pattern | Use instead |
|---|---|
| gray subtitles, gray annotations, in-plot notes ("qv>20", "n=") | caption text; black for all text |
| legends inside the plot | outside, tight to the panel |
| a legend repeating the row labels | the row labels |
| "†" as a marker | an asterisk |
| bold for significance | an asterisk after the value |
| long panel titles ("too long ... make it clear one thing and go") | 2 to 4 words |
| two redundant panels saying one thing | one panel |
| dense dot plots ("not obvious what they say") | the values shown directly (heat map with numbers, bars) |
| several near-identical bump charts in a row ("cryptic") | one rank heat map; one or two rank flows may stay when they carry a point |
| Z and p strips beside every panel, insignificant p in gray | the test results in the caption or a table, reported for every comparison alike |
| bars with black borders, thick bars | thin, borderless |
| a thicker line or bigger point for the own method | equal weight, locked hue |
| more than four type sizes | three tiers |
| a matplotlib concept schematic ("this is so bad") | a canvas schematic, or none |
| box frames around panels ("this is not a slide") | white space |
| panels stretched in the composer | panels drawn at their printed size |

## 5. Schematic

| Pattern | Use instead |
|---|---|
| tiny text sized on screen | type from the print arithmetic |
| panel background boxes, dividers | white space |
| circles for cell masks | organic polygons |
| case titles of different sizes | one size, shorter text |
| faint `#bbb` arrows | `#999` |
| a slide look (shadows, pills, 3-D, gradients) | flat blocks, thin borders |
| a cramped circuit (overlaps, no air) | budgeted white space, one flow direction |
| a key for the whole figure for a color only one panel uses | the column header, the icon, or the caption |
| one ellipsis across columns of different types | one group per type, each with its own ellipsis |
| a subtitle under every small table | a title that names the task and what is held out |

## 6. Vocabulary

Words the author used for bad design, so a note can be read correctly: "smells ai", "AI slop", "AI slides", "AI
bug" (a layout defect such as a broken line), "super AI" (rewritten text), "cringe and vague", "weird",
"underwhelming", "just a line plot", "noise", "pixelized" (coarse blocks at zoom), "ugly", "crowded",
"distraction", "clear AI slop flag".

Words for good design: "sexy", "super cool", "the nicest part", "close to perfect", "clean", "professional",
"like the highest-cited Nature papers of the last two years". The last one is an instruction: find such figures and
copy their grammar inside the house look.

Display copy follows the same rules: units follow the number ("[k] of [n] subsets"), real totals rather than rounded
marketing figures, "first" when first rather than "top 3", and retired terms stay retired once the author replaces
them.
